This guide walks you through the core TaskFlow workflow: creating a project, adding a task to it, and listing the tasks in that project. By the end, you will have made your first three API calls.

## Prerequisites

- Your API key
- - A terminal with `curl`, or an API client such as Postman

\<Info\>

The first request after a period of inactivity can take up to 60 seconds while the server starts. All later requests respond in under a second.

\</Info\>

## Step 1: Create a project

Every task in TaskFlow lives inside a project, so this is always the first call.

````text
TaskFlow endpoints depend on each other. This page explains the order of operations and what happens to a task during its lifecycle.

## The dependency chain

Each resource you create unlocks the next operations:

1. **Create a project** (`POST /projects`), which returns the `project_id`
2. **Create tasks** (`POST /tasks`) using a valid `project_id`
3. **List, update, or delete tasks** using a valid `project_id` or `task_id`

Skipping a step results in a `404 Not Found` error. For example, you cannot create a task before creating a project.

## The task lifecycle

Every task moves through three possible statuses:

| Status | Meaning |
| ------ | ------- |
| `pending` | The task has not been started. This is the default status for new tasks. |
| `in_progress` | The task is actively being worked on. |
| `done` | The task has been completed. |

To change a status, call `PATCH /tasks/{task_id}`:

```bash
curl https://test-writechoice.onrender.com/tasks/YOUR_TASK_ID \
  -X PATCH \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"status": "in_progress"}'
```
````

The response shows the new status. Note that `updated_at` changes, while `created_at` stays the same:

````text
json
{
  "task_id": "3272f799-9728-42f9-98ad-f99c8d21128d",
  "project_id": "15978c3f-e860-4372-b268-22be0fdabcda",
  "title": "My first task",
  "description": "Trying out the API",
  "status": "in_progress",
  "created_at": "2026-07-31T00:25:32.624Z",
  "updated_at": "2026-07-31T00:29:50.245Z"
}
```

## Deleting a task

When a task is no longer needed, delete it with `DELETE /tasks/{task_id}`:

```bash
curl https://test-writechoice.onrender.com/tasks/YOUR_TASK_ID \
  -X DELETE \
  -H "Authorization: Bearer YOUR_API_KEY"
```

<Warning>
Deleting a task is permanent and cannot be undone.
</Warning>

After deletion, listing the project's tasks confirms it is gone:

```json
{
  "project_id": "15978c3f-e860-4372-b268-22be0fdabcda",
  "total": 0,
  "tasks": []
}
```
````
